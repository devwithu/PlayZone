# 리뷰 정책 (초안)

> 상태: **확정** (2026-11-19, §12)
> 작성일: 2026-11-19
> 근거 문서: [기술 개발 설계서](../../00-overview/game-evaluation-development-design.md) §4.3, §4.10, §5.3, §6, §7.2 / [포인트 정책](./point-policy.md)

설계서가 정한 것은 다음 네 가지다. 나머지는 이 문서의 **제안**이다.

- 회원당 게임별 리뷰 1개 (권장)
- 평가 항목 7개(그래픽, 사운드, 스토리, 조작감, 게임성, 가성비, 종합), 1~10점
- 평균 점수는 공개된 리뷰만 집계
- 수정 이력, 비공개·승인 상태, 신고 처리 정책을 정의할 것

## 1. 공개 방식: 즉시 공개 + 사후 관리 (제안)

리뷰는 작성하면 **바로 공개**하고, 문제가 있는 리뷰는 **신고와 관리자 검토로 사후에 처리**한다.

| 방식 | 장점 | 단점 |
|---|---|---|
| **즉시 공개 (제안)** | 작성자가 바로 결과를 봄, 관리 부담이 적음 | 문제 리뷰가 신고 전까지 노출됨 |
| 승인 후 공개 | 문제 리뷰가 노출되지 않음 | 1인 운영으로는 모든 리뷰를 제때 승인하기 어려움, 승인이 늦으면 참여 의욕 저하 |

1인 개발·운영이므로 즉시 공개를 제안한다. 노출 위험은 §7 자동 블라인드로 줄인다.

## 2. 작성 자격

| 조건 | 기준 |
|---|---|
| 로그인 | 필수 |
| 가입 완료 | 약관 동의·닉네임 설정을 마친 회원만 (ADR-003) |
| 회원 상태 | `active`만. `suspended`(정지) 회원은 작성·수정 불가 |
| 리뷰 작성 제한 | §8 제재를 받은 회원은 기간 동안 작성 불가 |
| 게임 출시 여부 | **출시된 플랫폼이 하나 이상 있는 게임만** 리뷰 가능 |

## 3. 리뷰 1개 규칙

- 회원은 게임마다 **유효한 리뷰를 1개만** 가질 수 있다.
- 기존 리뷰를 고치려면 새로 쓰지 않고 **수정**한다.
- 본인이 리뷰를 삭제하면 같은 게임에 다시 쓸 수 있다. 단, 리뷰 작성 포인트는 다시 받지 않는다(포인트 정책 §5).
- 관리자가 숨긴(`hidden`) 리뷰가 있으면 같은 게임에 새 리뷰를 쓸 수 없다. 재검토는 관리자에게 문의한다.

DB에서는 `game_reviews(user_id, game_id)`에 **삭제되지 않은 리뷰만 대상으로 하는 부분 UNIQUE 인덱스**를 둔다 (PostgreSQL `WHERE status <> 'deleted'`).

## 4. 작성 내용

| 항목 | 필수 | 기준 |
|---|---|---|
| 제목 | 필수 | 2~50자 |
| 본문 | 필수 | 50~5,000자 |
| 종합 점수 | **필수** | 1~10 정수 |
| 세부 점수 6개 (그래픽·사운드·스토리·조작감·게임성·가성비) | 선택 | 1~10 정수, 입력한 항목만 저장 |
| 플레이한 플랫폼 | 필수 | 게임에 등록된 출시 플랫폼 중 1개 |
| 스포일러 포함 | 선택 | 체크하면 본문을 접어서 표시 |

- 점수는 DB에 CHECK 제약(1~10)을 둔다(설계서 §4.10).
- 본문 최소 50자는 포인트 정책의 리뷰 포인트 조건과 같다. 리뷰를 쓸 수 있으면 포인트 조건도 충족한다.
- 평가 항목은 `rating_categories`에서 관리자가 관리한다. 항목을 비활성화하면 새 리뷰에서만 빠지고, 기존 점수는 보존한다.

## 5. 상태

| 상태 | 의미 | 공개 | 평균 반영 | 바뀌는 경우 |
|---|---|---|---|---|
| `published` | 공개 | O | O | 작성 즉시, 관리자 복구 |
| `blinded` | 자동 블라인드, 관리자 검토 대기 | X | X | 신고 누적 (§7) |
| `hidden` | 관리자 숨김 (위반 확정) | X | X | 관리자 처리 |
| `deleted` | 작성자 삭제 | X | X | 작성자 삭제 |

- 실제 행 삭제(DELETE)는 하지 않는다. 상태만 바꾸고 데이터는 보존한다(설계서 §4.10).
- 숨김·블라인드 리뷰는 작성자 본인의 마이페이지에서만 상태와 사유를 보여 준다.

## 6. 수정과 삭제

**수정**
- `published` 상태에서만 본인이 수정할 수 있다. 횟수 제한은 없다.
- 수정할 때마다 이전 내용을 `review_revisions`에 저장한다(설계서의 "수정 이력").
- 수정된 리뷰에는 "수정됨"과 마지막 수정 시각을 표시한다.
- 수정으로 점수가 바뀌면 게임 평균을 다시 계산한다.
- 수정으로 포인트를 받지는 않는다.

**삭제**
- 본인은 언제든 삭제할 수 있다(`deleted`). 포인트는 회수하지 않는다(포인트 정책 §7).
- 삭제된 리뷰의 추천·댓글은 함께 숨긴다.

## 7. 신고와 자동 블라인드

**신고**
- 사유: 스포일러 미표시, 욕설·비방, 광고·스팸, 게임과 무관한 내용, 기타(직접 입력)
- 회원은 리뷰 하나에 **한 번만** 신고할 수 있다. 본인 리뷰는 신고할 수 없다.

**자동 블라인드**
- 서로 다른 회원 **5명**이 신고하면 리뷰를 자동으로 `blinded` 처리하고 관리자 검토 대기열에 올린다.
- 기준 인원은 관리자 설정에서 바꿀 수 있게 한다.

**관리자 처리 (Filament 리뷰 관리)**

| 처리 | 결과 | 포인트 |
|---|---|---|
| 기각 | `published`로 복구, 신고는 "기각"으로 종료 | 변동 없음 |
| 숨김 | `hidden`, 작성자에게 사유와 함께 알림 | 리뷰 작성 포인트를 `revoke`로 회수 (포인트 정책 §7) |

- 신고가 5건 미만이어도 관리자가 직접 숨길 수 있다.
- 모든 처리는 `admin_logs`에 남긴다.

## 8. 반복 위반 제재

| 조건 | 제재 |
|---|---|
| 최근 90일 안에 리뷰 3개 숨김 | 리뷰 작성 **60일** 제한 (2026-11-19 결정) |
| 제한 해제 후 다시 같은 조건 | 리뷰 작성 **영구 제한**. 관리자만 해제할 수 있다 (2026-11-19 결정) |
| 심각한 위반 (불법 정보 등) | 관리자가 회원 정지 (`suspended`) |

## 9. 평균 점수와 표시

- **게임 점수** = 공개(`published`) 리뷰의 **종합 점수 평균**. 소수점 첫째 자리까지 표시한다.
- 세부 항목 평균은 해당 항목에 점수를 준 리뷰만으로 따로 계산한다.
- 공개 리뷰가 **3개 미만**이면 점수 대신 "평가 부족"과 리뷰 수를 표시한다.
- 평균은 조회할 때마다 계산하지 않고 집계 컬럼에 저장한다. 리뷰 작성·수정·상태 변경이 커밋된 뒤 다시 계산한다.
- 탈퇴한 회원의 리뷰는 "탈퇴한 회원" 이름으로 계속 공개하고 평균에도 반영한다.

**리뷰 목록 정렬:** 추천순(기본), 최신순, 점수 높은순, 점수 낮은순

## 10. 추천

- 회원은 리뷰 하나에 한 번만 추천할 수 있다(`review_likes(user_id, review_id)` UNIQUE, 설계서 §4.10).
- 본인 리뷰는 추천할 수 없다.
- 추천을 취소할 수 있다. 취소 후 다시 추천해도 작성자 포인트는 다시 지급하지 않는다(포인트 정책 §5).
- 공개 상태가 아닌 리뷰는 추천할 수 없다.

## 11. 댓글

- 1~500자, 1차 오픈은 대댓글 없이 한 단계만 지원한다.
- 본인 댓글은 수정·삭제할 수 있다. 삭제한 댓글은 "삭제된 댓글입니다"로 표시한다.
- 댓글 작성 포인트는 게시판 댓글과 같은 `comment_create`로 지급하고, 일일 한도도 함께 센다(포인트 정책 §3).
- 댓글 신고는 1차 오픈 범위에서 제외하고, 관리자가 직접 숨긴다.

## 12. 결정 사항

2026-11-19에 다음과 같이 결정했다.

| # | 질문 | 결정 |
|---|---|---|
| 1 | 즉시 공개인가, 승인 후 공개인가? | **즉시 공개 + 사후 관리** (§1). 리뷰 작성 포인트는 작성 즉시 지급한다 |
| 2 | 출시 전 게임에도 리뷰(기대평)를 허용하는가? | **1차 오픈은 허용하지 않는다** |
| 3 | 세부 점수 6개를 필수로 할 것인가? | **종합 점수만 필수**, 세부 점수 6개는 선택 |
| 4 | 자동 블라인드 기준 인원은? | **5명** (관리자 설정으로 변경 가능) |
| 5 | 평균 표시 최소 리뷰 수는? | **3개** |
| 6 | 반복 위반 제재 기준은? | 1차: 90일 안에 3개 숨김 → **60일 제한**. 재위반: **영구 제한** (관리자만 해제) |

## 13. 설계서 대비 DB 변경 제안

ERD 작업 때 반영한다.

| 테이블 | 변경 | 이유 |
|---|---|---|
