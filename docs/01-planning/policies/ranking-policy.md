# 랭킹 정책

- 상태: 확정 (2026-11-21)
- 관련: REQ-508, REQ-509(P2), 화면 설계 W-13, ERD §8 `ranking_snapshots`, API 명세 §7.6 `GET /rankings`
- 구현: `App\Services\RankingService`, `App\Enums\RankingType`, 명령 `rankings:snapshot`

## 1. 랭킹 종류

| 코드 | 이름 | 기간 (KST) | 점수 |
|---|---|---|---|
| `points_weekly` | 주간 포인트 | 월요일 0시 ~ 일요일 24시 | 기간 안에 **활동으로 받은 포인트** 합계 |
| `reviews_monthly` | 월간 리뷰 | 매월 1일 0시 ~ 말일 24시 | 기간 안에 쓴 리뷰 중 **지금 공개 상태인** 리뷰 수 |

랭킹 종류 추가와 보상은 2차(REQ-509)에서 정한다.

## 2. 점수 규칙

### 2.1 주간 포인트

- 넣는 사유: 출석, 7일·30일 연속 출석 보너스, 리뷰 작성, 리뷰 추천받음, 게시글 작성, 댓글 작성.
- 빼는 사유: 회원가입, 이벤트 보상, 관리자 지급. 활동량을 겨루는 랭킹이라 활동과 무관한 지급은 넣지 않는다.
- 회수: 적립이 나중에 회수되면, 그 적립이 속한 주의 점수에서 회수한 만큼 뺀다.
- 사용(이벤트 응모, 관리자 차감)은 점수를 줄이지 않는다.
- 날짜는 원장의 `service_date`(KST 기준 서비스 일자)로 판단한다.

### 2.2 월간 리뷰

- 리뷰 작성 시각(`created_at`, UTC 저장)을 KST로 바꿔 그 달에 속하면 센다.
- 검토 중(blinded)·숨김·삭제된 리뷰는 세지 않는다. 집계 때의 상태를 따르므로, 나중에 숨겨지면 다음 집계부터 빠진다.

### 2.3 공통

- 정상(active) 회원만 순위에 든다. 정지·탈퇴·가입 미완료 회원은 빠진다.
- 점수가 0 이하이면 순위에 넣지 않는다.
- 같은 점수는 같은 순위다(1, 1, 3 …). 같은 순위 안의 표시 순서는 회원 번호 순이다.

## 3. 집계 주기

- 스케줄러가 **매시 정각**에 이번 기간을 다시 집계한다. 화면에는 마지막 집계 시각을 보여 준다.
- 새 기간의 첫날(월요일, 1일)에는 지난 기간도 매시 다시 집계해, 기간 끝 무렵의 활동과 늦은 회수를 반영한다. 그 뒤로 지난 기간 결과는 바뀌지 않는다.
- 한 기간의 결과는 트랜잭션 안에서 지우고 다시 넣는다. 조회 중에 반쯤 바뀐 순위를 보지 않는다.
- 운영 서버에는 cron `* * * * * php artisan schedule:run`이 있어야 한다. 개발 중에는 `php artisan rankings:snapshot`으로 직접 집계하거나 `php artisan schedule:work`를 띄운다.
- 특정 기간만 다시 집계: `php artisan rankings:snapshot --type=points_weekly --date=2026-11-18`.

## 4. 보여 주기

- 상위 100위까지 보여 준다. 점수가 0보다 큰 회원은 모두 저장하므로, 로그인 회원은 100위 밖이어도 "내 순위"를 볼 수 있다.
- 순위에 없는 로그인 회원에게는 "아직 순위에 없어요"를 보여 준다.
- 이전 기간은 첫 집계가 있는 기간까지, 다음 기간은 이번 기간까지 이동할 수 있다. 미래 날짜를 요청하면 이번 기간을 보여 준다.
- 탈퇴한 회원이 지난 랭킹에 남아 있으면 "탈퇴한 회원"으로 보여 준다.
