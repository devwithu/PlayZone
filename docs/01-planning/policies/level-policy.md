# 회원 등급 정책

> 상태: **확정** (2026-11-21)
> 근거 문서: [포인트 정책](./point-policy.md) §9, [ERD](../../03-architecture/database/erd.md) §8

## 1. 기준

- 등급은 **누적 획득 포인트**(`users.lifetime_points`)로 정한다. 포인트를 써도 등급은 내려가지 않는다.
- 포인트 회수(`revoke`)는 누적 포인트에서도 빠지므로, 부정하게 올린 등급은 내려간다.
- 회원의 등급은 누적 포인트가 기준값 이상인 등급 중 가장 높은 것이다.

## 2. 시작 등급

| 등급 | 기준 누적 포인트 |
|---|---:|
| 브론즈 (기본) | 0 |
| 실버 | 1,000 |
| 골드 | 4,000 |
| 플래티넘 | 10,000 |

이름과 구간은 **관리자 화면(포인트·등급 > 회원 등급)에서 추가·변경·삭제**한다. admin 이상만 바꿀 수 있다.

## 3. 관리자 변경 규칙

| 변경 | 처리 |
|---|---|
| 등급 추가, 기준값 변경 | 저장 후 큐 작업으로 전체 회원 등급을 다시 계산한다. 탈퇴 회원은 제외한다 |
| 등급 삭제 | 그 등급 회원을 바로 아래 등급으로 옮긴 뒤 삭제한다 |
| 기본 등급(0P) | 이름·아이콘은 바꿀 수 있지만 기준값은 0으로 고정이고 삭제할 수 없다 |
| 이름·기준값 | 중복 불가 |

- 등급이 바뀐 회원은 `user_level_histories`에 남긴다. 사유는 `earn`(적립), `revoke`(회수), `admin`(관리자 변경으로 재계산)이다.
- 등급 변경 알림(오름·내림)은 4단계 알림 기능에서 붙인다. 관리자 변경으로 등급이 내려가는 회원에게는 우선 알리지 않는다.

## 4. 표시

- 앱 `GET /auth/me`, `GET /points/balance`는 현재 등급(`level`)과 다음 등급까지 남은 포인트(`next_level.points_needed`)를 준다. 가장 높은 등급이면 `next_level`은 `null`이다.
- 마이페이지(W-17)의 "골드까지 600P"는 이 값으로 표시한다.
