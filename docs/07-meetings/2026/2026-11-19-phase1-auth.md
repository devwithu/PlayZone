### 소셜 로그인 구현 요약

- 스타터 키트의 비밀번호·가입·재설정·이메일 인증·2FA·패스키 기능을 지웠다. Fortify는 설치된 채 `features => []`와 `Fortify::ignoreRoutes()`로 꺼 두었다.
- 테이블: `users`(ERD대로, `password` NULL 허용 유지), `roles`·`role_user`(기본 역할 4개), `social_accounts`, `withdrawn_identity_hashes`.
- 웹 흐름: `/login` → `/auth/{provider}/redirect` → `/auth/{provider}/callback` → 처음이면 `pending` 회원 생성 후 `/signup/complete` → 가입 완료 시 `active`와 `member` 역할.
- 주요 코드: `SocialLoginService`, `SignupService`, `SocialLoginController`, `SignupController`, 미들웨어 `signup.completed`·`signup.pending`.
- 테스트는 `Socialite::fake()`로 작성했다(37개 통과). **실제 OAuth 키로는 아직 확인하지 않았다.**

## 결정 사항

- 이메일·비밀번호 가입은 지금 만들지 않지만, 나중에 추가할 수 있게 비밀번호 칸·재설정 테이블·Fortify를 남긴다 (ADR-003 §8).
- 같은 이메일이라도 다른 로그인 수단이면 자동으로 합치지 않는다. 새 회원의 `users.email`은 비워 두고 `social_accounts.email`에만 저장한다.
- 화면에 공유하는 회원 정보는 `id`, `nickname`, `status`, `point_balance`만 보낸다. 이메일은 보내지 않는다.
- 가입 포인트 지급은 3단계에서 `PointService`를 만들 때 `SignupService::complete()`에 붙인다.
